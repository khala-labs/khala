# Observer 회고 실행 — 머지된 PR 30건 (2026-11-08)

## 질문
Observer를 CI에 연동하기 전, 본 저장소의 최근 머지된 PR을 대상으로 실행했을 때 발화율이 얼마인지, 그리고 가설에서 명시한 논리적 응집도(cohesion)에 의해 발화하는지 아니면 단순 크기 임계값에 의해 발화하는지 검증합니다. 실행 전 정의한 판정 기준은 발화율이 10% 이상 60% 이하 범위에 들 경우에만 CI 작업을 연동한다는 규칙입니다.

## 방법
본래 저장소(`LivingLikeKrillin/khala`)의 최근 머지된 PR 30건(PR #552–#582, 머지 기간 2026-09-23 ~ 2026-10-18)을 임시 클론에서 스쿼시 머지 커밋별로 체크아웃하여 분석을 진행했습니다. 분리된 독립 저장소(`khala-labs/observer`, 2026-11-08 아카이브)에서 빌드한 Observer v0.6.0을 사용하였으며, 각 커밋에서 `observer check --base <merge-commit>~1 --format json` 명령을 실행했습니다.

Observer는 기본 제공 프로필(Spring Boot, Next.js, React SPA)만 지원하며 본 저장소의 Python 모노레포 구조는 감지하지 못합니다. 따라서 저장소 구조를 반영한 커스텀 프로필을 작성했습니다. 최상위 디렉터리 경로 기준 파일 역할(Nexus 코어, 테스트, 스크립트, 마이그레이션, 문서, 개별 도구, 기록, 문서 사이트, 가드 스크립트, CI), 5개 응집도 그룹, 그리고 저장소 자체 컨벤션에서 가져온 6개 관심사 혼합(mixed-concern) 규칙(PR당 단일 도구 수정, SPEC/ADR 문서와 구현 코드 분리, 전체 가드 스크립트와 프로덕트 코드 분리 등)을 정의했습니다.

실험은 두 가지 프로필 버전으로 실행했습니다:
- **v1**: Observer 기본 스타일 크기 임계값 적용 (파일 15개 초과, diff 600줄 초과, 응집도 그룹 2개 초과 시 경고).
- **v2**: 파일 및 라인 수 임계값을 발화하지 못할 정도로 높여 응집도 규칙(2개 초과 그룹 또는 관심사 혼합 규칙 위반)만 단독으로 검증.

Windows 환경 실행 참고 사항: Observer는 `cmd.exe`를 통해 git을 호출하므로, 베이스 참조에 `<sha>^`를 사용하면 `^`가 이스케이프 문자로 처리되어 변경 파일이 0건으로 인식됩니다. `<sha>~1` 형식을 사용해야 정상 동작합니다.

## 결과

| **v2** (응집도 규칙 단독) | 2 / 30건 | 7% | #579 (그룹 4개), #580 (그룹 3개 및 가드/코드 분리 위반) |

- **v1 결과**: 30건 중 8건(27%)에서 경고가 발생했습니다. 발화한 8건 모두 파일 수 임계값 초과가 원인이었습니다. 이 중 3건은 diff 600줄을 초과했고, 2건은 응집도 그룹 2개를 초과했으며, 1건은 관심사 혼합 규칙에 걸렸습니다. 파일 수 임계값을 넘지 않고 응집도 규칙 단독으로 경고를 발생시킨 PR은 없었습니다.
  - 경고 발생 8건: 전체 용어 정비 작업 `docs(terms)` #576–#580 (각 18~391개 파일, 의도된 전역 수정), #574 (README 다이어그램, 22개 파일), #558 (프롬프트 버전 변경, 16개 파일), #553 (클레임 판정 추가, 19개 파일).
- **v2 결과**: 30건 중 2건(7%)인 #579, #580에서만 경고가 발생했습니다. 두 건 모두 저장소 전체 디렉터리를 의도적으로 수정한 용어 정비 작업이며, 해당 PR에 대한 분할 제안은 실질적인 조치 가치가 없습니다. v1에서 경고를 발생시키지 않은 22건의 PR은 v2에서도 발화하지 않았습니다.

## 판정
사전 정의된 판정 규칙(발화율 10~60%)과 대조한 결과는 다음과 같습니다:
- v1의 발화율(27%)은 기준 범위 내에 들지만, 발화 원인의 100%가 가설에서 지양하는 단순 파일 수 임계값에서 기인했습니다.
- 핵심 가설인 응집도 규칙만을 격리한 v2의 발화율은 7%로 기준 하한선(10%)에 미달하며, 발화된 2건 역시 전역 수정에 대한 유의미하지 않은 경고였습니다.

현재 조건에서 응집도 가설은 30건의 PR에 걸쳐 유의미한 경고를 만들어내지 못했으므로 CI 작업을 연동하지 않습니다. 본 결과는 해당 저장소, 해당 기간, 작성된 프로필 조건에 한정되며, Observer가 기본 지원하는 플랫폼 환경을 테스트한 결과는 아닙니다.

## 조건과 한계
1. **프로필 작성 주체**: 프로필을 Observer가 생성하지 않고 실험 수행자가 직접 작성했습니다.
2. **저장소 특성**: 1인 개발 저장소로서 컨벤션과 Arbiter 게이트를 통해 이미 단일 관심사가 유지되고 있어, 응집도 분석기 관점에서는 가장 비우호적인 대상입니다.
3. **리뷰 영향 미측정**: 작성자와 리뷰어가 동일하여 경고가 실제 리뷰 진행을 변화시켰는지 여부는 측정할 수 없었습니다.
4. **미검증 기능**: 설정 경로에 OpenAPI 사양이 없어 Observer의 다른 기능인 API 계약 린트 및 체크리스트 생성 기능은 검증하지 않았습니다.
