# 기권 게이트 1단계 기준선 — 판정기 3회 실행 (2026-11-28)

## 질문
SPEC-nexus-abstention-gate §3.3 1단계 규정에 의거하여, Pack B를 대상으로 현행 충분성 판정기의 과잉 기권율, 탐지율, 판정 지연 시간 기준선을 측정하였다. 본 측정은 Unit 2 진입 전 판정기가 기권 게이트 하한선 기준을 충족하는지 검증하고 기준 파일 생성 요건을 충족하는지 확인하기 위해 수행되었다.

- 실행 일시: 2026-11-28에 실행하였다.
- 실행 환경: 비용이 발생하지 않는 keyless bridge 환경을 이용하였다.
- 실행 도구: 기록기는 nexus/scripts/ko_eval_sufficiency_run.py, 채점기는 nexus/scripts/ko_eval_sufficiency_score.py를 사용하였다.
- 데이터셋 설정: packb-labels.yaml revision 9, 테넌트 default, 보안 등급 INTERNAL, 타임아웃 120 s를 적용하였다.
- 백엔드 및 모델: backend claude-code, 모델 설정 claude-sonnet-5를 적용하였다.
- 프롬프트 및 파서 해시: 프롬프트 SHA-256 1c940f44f693…, 파서 SHA-256 cc5d64df07bd…로 3회 실행 모두 동일하게 유지하였다.
- 판정기 정의: nexus/nexus/llm/sufficiency.py의 판정기는 단일 호출로 동작하며, 근거만으로 확정적 답변이 가능하면 충분(sufficient), 정보 결여·부분적·불확정적이거나 모순되면 불충분(insufficient)으로 정의한다.
- 판정기 출력 및 파싱: 출력은 VERDICT: 및 REASON: 두 행으로 구성되며 정규식으로 파싱한다.
- 평가 대상 집단: 정답 제시 가능 라벨 39건을 대상으로 평가하였다. 골드 문서가 패킷에 도달하지 못한 정답 제시 가능 라벨 1건은 평가 대상에서 제외하였다.
- 대조군 미실행: --controls 옵션을 사용하지 않아 정답 불가 대조군은 실행하지 않았다.
- 실행 규모 및 소요 시간: 매 회차당 78회의 판정기 호출을 수행하였으며 회차당 약 9분이 소요되었다.
- bridge 동시성: NEXUS_LLM_BRIDGE_CONCURRENCY=3 설정을 적용하였다.

## 기준과의 대조
- 하한선 규정: SPEC-nexus-abstention-gate §3.3 0단계에 규정된 통과 하한선은 X(최대 과잉 기권율) ≤ 5%, Y(최소 탐지율) ≥ 80%, Z(최대 추가 p95 지연) ≤ 10 s이다.
- 하한선 미달: 3회의 실행 모두 과잉 기권율(10.3–20.5%)이 X 하한선을 초과하였고, 탐지율(71.8–76.9%) 역시 Y 하한선에 미달하였다.
- 지연 기준 초과: run 3의 p95 지연 시간은 10,598 ms로 Z 기준(10 s)을 넘었다(run 1은 9,775 ms, run 2는 8,644 ms).
- 도달 가능성 검토: §3.3 3단계에 따른 도달 가능성 검토 결과, 허용 가능한 X 구간 중 기준선 통과 범위에 속하는 구간이 없고, 허용 가능한 Y 구간 역시 통과 범위에 속하지 못하였다.
- 기준 파일 작성 불가: 하한선 미충족으로 인해 기준 파일(criteria file)은 작성되지 않았다.
- Unit 2 폐쇄 유지: §3.3 6단계에 따라 Unit 2는 진입이 불가능한 폐쇄 상태를 유지한다.
- 수치 기록 및 향후 절차: §3.3 6단계에 따라 수치를 이 문서에 기록한다. 판정기를 바꾸면 새 판정기 식별 정보로 1단계부터 다시 측정한다.

## 음성 실험군에 답이 남아 있다
- 사후 검증 배경: 3회 실행 완료 후 LLM 호출을 배제하고 음성 실험군 패킷 내 정답 잔류 여부를 확인하였다.
- 검증 절차: 39개 라벨 전건에 대해 기록기와 동일한 retrieve_for_answer 경로로 패킷을 다시 구성하고 골드 문서를 제외한 뒤, nexus/scripts/ko_eval_answer_quality.py의 facts_present 함수를 통해 format_for_llm(packet) 텍스트 내 must_contain 그룹 포함 여부를 확인하였다.
- 전체 패킷 결과: 골드 문서가 포함된 정답 제시 가능 패킷 39건 전건(39/39)이 모든 must_contain 그룹을 온전히 포함하였다.
- 음성 패킷 잔류 현황: 골드 문서를 제외한 음성 패킷 39건 중 16건(16/39)은 여전히 모든 must_contain 그룹을 포함하고 있었으며, 포함하지 않는 패킷은 23건(23/39)이었다.
- 탐지율 상한선: 정답 정보가 남아 있는 16건에 대해 올바르게 충분(sufficient) 판정을 내리는 판정기는 본 실험군에서 최대 23/39 = 59.0%의 탐지율만 기록할 수 있으며, 이는 규격 하한선인 80%에 미달한다.
- 하한선 도달의 모순: 본 음성 실험군에서 80% 하한선에 도달하려면 정답 정보가 포함된 패킷을 불충분으로 오판해야만 한다.
- 현행 판정기 반응: 현행 판정기는 3회 실행 모두에서 해당 16건 중 8건을 불충분으로 판정하였다.
- 충분 판정 라벨 분포: 음성 실험군에서 최소 1회 이상 충분 판정이 내려진 11개 라벨 중 8건이 이 16건에 포함되었다.
- 정답 정보가 결여된 23개 패킷 실측치: 불충분 판정 비율은 run 1에서 20/23(87.0%), run 2에서 21/23(91.3%), run 3에서 21/23(91.3%)이었다.
- 미탐지 라벨 현황: 23개 패킷 집단에서 3회 모두 탐지에 실패한 라벨은 2건, 1회 실패한 라벨은 1건이었다.
- 진단 목적 한정: 상기 23건 하위 집단은 실행 후 사후에 분류된 것이므로 진단 목적(diagnostic-only)으로만 해석해야 하며 공식 평가 결과로 취급할 수 없다.
- 스트링 매칭의 한계: must_contain 포함 검증은 스트링 매칭에 의존하므로, 의미상 통하는 다른 표현을 감지하지 못하고 다른 문맥에서 일치한 텍스트를 오인할 수 있다.
- 규격서 기술 결함: SPEC-nexus-abstention-gate §3.2 2항은 음성 대상을 골드 문서를 제외한 정답 가능 라벨 집단으로 정의하며 탐지율을 하한선(lower bound)이라 기술하였으나, 올바른 판정기의 탐지율 상한이 59.0%로 제한되므로 이 표현은 문제를 실제보다 작게 적은 것이다.
- 철회 절차: 서명된 본문은 고치지 않는다. 초안 SPEC-nexus-abstention-gate-negative-arm 이 승인되면 CONVENTIONS.md §Retracting a claim in a signed document 에 따라 records/specs/retractions.yaml 에 철회 항목을 넣고 프론트매터에 retractions: 포인터를 더한다.

## 과잉 기권의 이유
3회 실행 통틀어 정답 제시 가능 실험군에서 불충분(insufficient) 판정이 내려진 사례는 총 20건(고유 라벨 12건, 3회 모두 불충분 판정 2건)이었다. 판정기의 REASON 출력 행을 검토하여 분류한 결과는 다음과 같다.

| 사유 분류 | 판정 건수 |
|---|---|
| 근거 문서 상호 간 내용 충돌(주로 구버전과 신버전 정책 간 불일치) | 6 |
| 질문에서 요구하지 않은 세부 사항 요구(구체적 구현 단계, 수치, 직접 비교 등) | 9 |
| 근거 문서는 예시 값을 제시하였으나 질문이 프로젝트의 실제 결정을 요구한 것으로 해석 | 3 |
| 질문의 조건 명시 미흡(특정 필드 미지정, 노출의 의미 모호 등) | 2 |

상기 사유 분류는 기준선을 실행한 에이전트 한 명이 REASON 행을 읽고 분류한 것이며, 다른 사람의 검토를 거치지 않았다.

## 실행 중 사고
기준선 측정 초기 2회의 시도에서 모든 호출이 브리지로부터 HTTP 403 오류("bad or missing X-Bridge-Token")를 반환하였다. 원인은 .env 환경 설정의 브리지 토큰이 갱신되기 전에 애플리케이션 컨테이너가 생성되었기 때문이었다. 애플리케이션 컨테이너를 다시 생성하여 정상 통신을 복구하였다. 비정상 종료된 초기 2회의 산출물은 유효한 측정 데이터가 아니므로 채점하지 않고 tests/eval/local/invalid-bridge-403/ 경로로 격리 보관하였다.

## 한계
- 스트링 매칭의 한계: must_contain 포함 여부 확인이 단순 스트링 매칭 방식으로 수행되어, 문맥이 다른 동일 어구를 정답으로 오인하거나 다른 어휘로 표현된 내용을 인식하지 못할 가능성이 있다.
- 단일 평가인의 단독 분류: 과잉 기권 사유 분석은 기준선을 실행한 에이전트 한 명이 수행하였으며, 다른 사람의 검토를 거치지 않았다.
- 과거 수치와의 비교 불가: SPEC-nexus-abstention-gate §3.1의 과거 수치(과잉 기권 2/40, 탐지율 81.6%)는 기준선을 본 뒤에 좁힌 이전 모집단 규칙을 썼고 공용 응답 프론트엔드를 거치지 않은 별개 하네스 환경에서 도출되었으므로 본 측정 결과와 직접 비교할 수 없다.
- 대조군 미실행: --controls 플래그를 사용하지 않아 정답 불가 대조군에 대한 측정을 수행하지 않았다.
