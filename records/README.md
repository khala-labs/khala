# records

2026-11-08에 `khala-labs/khala` 저장소는 루트에 있던 8개의 의사결정 기록 및 실무 문서를 이 단일 디렉터리로 통합했습니다. 내부 내용은 일체 수정되지 않았으며 위치만 변경되었습니다. 모든 파일이 함께 이동했으므로 SPEC에서 연구 노트로 향하는 링크 등 디렉터리 내부 파일 간의 상대 링크는 그대로 정상 동작합니다.

| 이름 | 설명 | 작성 방식 |
| :--- | :--- | :--- |
| `specs/` | `README.md`, `backstop-debt.yaml`, `retractions.yaml`을 포함하는 설계 사양서(54개의 `SPEC-*.md`) | Arbiter가 작성 및 날인하며, 철회 목록과 백스톱 목록은 수작업으로 작성합니다. |
| `adr/` | `README.md`를 포함하는 아키텍처 결정 기록(10개의 `ADR-*.md`) | Arbiter가 작성 및 날인합니다. |
| `.reviews/` | 비평 사이드카(`SPEC-*.md`, `ADR-*.md`) 및 disposition 입력 파일(`dispositions-*.json`) | 사이드카는 Arbiter의 비평 단계에서 생성되며, disposition 파일은 수작업으로 작성되어 `arbiter approve --dispositions`가 읽습니다. |
| `INDEX.md` | 모든 SPEC 및 ADR의 상태 색인 | Arbiter가 생성하며, 수작업으로 편집하지 않습니다. |
| `governance/` | `integrity-manifest.txt`(CI가 날인 본문을 검증하는 ID 목록) 및 `open-items.yaml` | CI `governance` 작업의 `scripts/ledger_integrity.py`가 읽습니다. |
| `research/` | 다른 조직이 동일한 문제를 해결한 방식을 조사한 문서(`YYYY-MM-DD-<slug>.md`) | 수작업 작성(SPEC 또는 ADR이 아닙니다). |
| `audit/` | 날짜가 명시된 감사 보고서 | 수작업으로 작성합니다. |
| `plans/` | 사양서와 짝을 이루는 구현 계획서(`YYYY-MM-DD-<slug>.md`) | 수작업으로 작성합니다. |

현재 자체 저장소(`https://github.com/khala-labs/arbiter`)로 분리된 Arbiter는 단일 디렉터리를 원장 루트로 취급하며, 그 바로 아래에 `specs/`, `adr/`, `.reviews/`, `INDEX.md`가 위치할 것으로 예상합니다. CLI, MCP 서버, `PreToolUse` 훅 모두 환경 변수 `ARBITER_DOCS`에서 해당 루트를 읽습니다. 이 저장소의 경우 `ARBITER_DOCS`는 반드시 이 `records/` 디렉터리를 가리켜야 하며, 이전 값이었던 저장소 루트는 더 이상 동작하지 않습니다.

미결 항목 등록부인 `OPEN.md`, 용어집인 `GLOSSARY.md`, 규칙 문서인 `CONVENTIONS.md`는 CI 점검과 용어 훅이 해당 위치에서 읽기 때문에 저장소 루트에 유지됩니다.

## English

On 2026-11-08, the repository `khala-labs/khala` gathered its decision records and working notes, which had been eight items at the repository root, under this one directory. Nothing inside them was rewritten; only their location changed. Relative links between files in this directory (for example from a SPEC to a research note) keep working because everything moved together.

| Name | What it is | Who writes it |
| :--- | :--- | :--- |
| `specs/` | Design specifications (`SPEC-*.md`, 54 of them) with `README.md`, `backstop-debt.yaml` and `retractions.yaml` | Written and stamped by Arbiter; retractions and the backstop list by hand |
| `adr/` | Architecture decision records (`ADR-*.md`, 10) with `README.md` | Written and stamped by Arbiter |
| `.reviews/` | Critique sidecars (`SPEC-*.md`, `ADR-*.md`) and disposition inputs (`dispositions-*.json`) | Sidecars by Arbiter's critique step; dispositions by hand, read by `arbiter approve --dispositions` |
| `INDEX.md` | The status index of every SPEC and ADR | Generated by Arbiter; do not edit by hand |
| `governance/` | `integrity-manifest.txt` (the ids whose stamped bodies CI verifies) and `open-items.yaml` | Read by `scripts/ledger_integrity.py` in the CI `governance` job |
| `research/` | Surveys of how other organisations solve the same problems (`YYYY-MM-DD-<slug>.md`) | By hand; neither SPEC nor ADR |
| `audit/` | Dated audit reports | By hand |
| `plans/` | Implementation plans paired with specs (`YYYY-MM-DD-<slug>.md`) | By hand |

Arbiter (now in its own repository, `https://github.com/khala-labs/arbiter`) treats one directory as its ledger root and expects `specs/`, `adr/`, `.reviews/` and `INDEX.md` as siblings directly under it. It reads that root from the environment variable `ARBITER_DOCS` (the CLI, the MCP server and the `PreToolUse` hook all do). For this repository `ARBITER_DOCS` must point at this `records/` directory; the earlier value, the repository root, no longer works.

The open-items register `OPEN.md`, the glossary `GLOSSARY.md` and the conventions `CONVENTIONS.md` stay at the repository root because CI checks and the terminology hook read them there.
